Join the matrix — three doors, one gate

Payment meters admission. Only the cryptographic + conformance checks decide validity — never one substituting for the other.

1 · Submit a claim

POST a signed verdict to the registered intake — invinoveritas /ledger/submit ↗ (self-describing: GET it for fields, price, and flow — 150 sats via Lightning top-up or x402 USDC on Base, registration free, signature-verified, publishes immediately on success). A public CI watcher polls the ledger every 30 minutes, runs every entry through the pre-hash conformance gate, and registers conforming claims in claims/. Nonconforming-but-paid submissions are published in claims/rejected/ with the gate error — a rejection is a derivable fact, never a silent drop.

2 · Cross-verify a claim (registered nodes)

Recompute the claim from its source, sign a crc.cell.v3 Cell under your registered key, and open a PR to cells/{claim_id_hex}/{node_id}.cell.json. New here? ONBOARDING.md walks it end to end, and CELL-v2.md is the format you sign against. CI runs the full mechanical review — gate, claim_id, as_of binding, and your envelope's signature check against the registered key (never the key the cell asserts). Green merges; your column earns its lamp here. One-liner check before you PR: recompute-step crc/cell-verify <cell.json> eip712 <registered address> (recompute-kit).

3 · Register a lane

One PR adding one node object to nodes.json per NODES.md: identity, lane, envelope (nostr-nip01 or eip712), and a checkable key reference. If it parses, conforms, and the key is checkable, it merges — no other approval step. Retirement is a tombstone, never a deletion.

Your footprint in the matrix

No login — everything here is public and content-addressed. Enter a GitHub handle, an 0x address, or a claimant id; the report derives on your machine, live from the repo and registry.

Recomputed in your browser from public data. No trust required.

Node 2 is fetched live from GitHub raw (the signed crc.cell.v0). Node 1 and the /ledger #236 source are embedded from Fede's published /verify-proof (his endpoint isn't CORS-open, so a browser can't fetch it cross-origin — we don't proxy it, as a proxy would insert a trust dependency; the links above let you diff against the live source yourself). Recompute uses SubtleCrypto (sha256), @noble/curves (BIP-340 schnorr), and ethers (keccak256 + EIP-712 recover) — all client-side.

Every cell runs the pre-hash conformance gate before hashing (exact field set, duplicate-member rejection on the raw text, hash grammar, claimant range, strict as_of) — the same predicates as reference/claim_id.py. EIP-712 cells require triple equality: recovered signer == signature.signer == proof_payload.verifier. AMBER abstains — an unreachable dependency or source is an observation failure, never a mismatch; only a computed mismatch earns RED.
